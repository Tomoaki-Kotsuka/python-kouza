# Excel 操作を Python でやってみよう

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/Tomoaki-Kotsuka/python-kouza/blob/main/python_excel_kouza.ipynb)

プログラミング未経験で、Excel をふだん使っている人向けの Python 入門講座です(40分〜1時間)。Excel でやっている「開く・集計する・シートをまとめる・ファイルを分ける」を Python で動かし、3年分・約3000行の売上データを 20フォルダ・20ファイルに数秒で分割するところまで体験します。

## 受講者の方へ: 始め方(3ステップ)

1. 上の **Open in Colab** ボタンを押す(Google アカウントでログインしておく)
2. Colab のメニューで **「ファイル → ドライブにコピーを保存」** を押す
3. 上のセルから順に **`Shift + Enter`** で実行していく

- インストールもファイルのアップロードも不要です。使う Excel データは、ノートブックが自動で用意します
- 「このノートブックは Google が作成したものではありません」と出たら「このまま実行」を押してください
- 赤い文字のエラーが出たら、上のセルから順にもう一度実行すれば直ります

## ファイル

- `python_excel_kouza.ipynb` … 講座のノートブック(説明とコード)。これ1つで講義が完結する
- `sales_data.xlsx` … 元データ(2023〜2025年度の架空の売上明細。3シート、各約1000行、20地区)
- `make_sales_data.py` … `sales_data.xlsx` を作り直すスクリプト(乱数シード固定。何度作っても同じデータ)
- `split_by_area.txt` … 比較用の VBA(講師だけが Mac 版 Excel で実行)。貼り付け用・UTF-8
- `split_by_area.bas` … 同じ内容のインポート用(Shift_JIS・CRLF)。Windows 版 Excel で使うとき用

データに出てくる担当者名・商品・金額はすべて架空のものです。

## VBA(比較用)の準備と実行(Mac 版 Excel)

`split_by_area.txt` は、ノートブックの 3章 + 5章 と同じ処理(年度シートの列順を揃えて統合 → 地区ごとにフォルダを作って地区別ブックを保存)を VBA で書いたものです。コードの量と処理時間を Python と見比べる目的で使います。

事前準備(講座の前に1回やっておく)

- `sales_data.xlsx` を Mac 上のふつうのフォルダに置く。OneDrive / iCloud Drive / SharePoint 上のフォルダは避ける(保存先を作れないため、マクロがメッセージを出して止まる)
- Excel で新しい空のブックを作る
- メニューバーの「ツール → マクロ → Visual Basic Editor」で VBE を開く(「開発」タブを使う場合は「Excel → 環境設定 → リボンとツールバー」で「開発」にチェックを入れ、「開発 → Visual Basic」)
- VBE の「挿入 → 標準モジュール」で空のモジュールを作る
- `split_by_area.txt` をテキストエディット(または VS Code)で開き、全部コピーしてモジュールに貼り付ける
- Excel に戻り、「ファイル → 名前を付けて保存」でファイル形式を「Excel マクロ有効ブック (.xlsm)」にして、`sales_data.xlsx` と同じフォルダに `split_by_area.xlsm` として保存する
- 一度リハーサルで実行しておく(下の「実行」の手順)。アクセス許可はこのとき済ませておけば、本番ではダイアログが出ないか、出ても1回で済む

実行(講座当日)

- `split_by_area.xlsm` を開く。「マクロを有効にする」を聞かれたら有効にする
- `sales_data.xlsx` を開き、こちらを手前に表示する
- 「ツール → マクロ → マクロ...」で `SplitByArea` を選んで「実行」
- 最初に「アクセス権を付与」のダイアログが出たら、表示されたフォルダのまま「アクセス権を付与」を押す(出るのは最初の1回だけの想定。処理時間は許可の後から計り始める)
- 終わると、地区数・処理時間・出力先がメッセージで表示される
- 出力先は `sales_data.xlsx` と同じフォルダの `地区別_VBA`。そこに書き込めなかったときは Excel 専用の作業フォルダ(`~/Library/Containers/com.microsoft.Excel/Data/地区別_VBA`)に保存し、メッセージに実際の場所を出す
- `sales_data.xlsx` 自体は書き換えない。やり直すときはそのまま再実行でよい(同じ名前のファイルは上書きされる)

文字コードと日本語について

- Mac では `split_by_area.txt`(UTF-8)からのコピペを使う。VBE の「ファイルのインポート」は文字コードの扱いが確認できていないので、Mac では使わない
- 貼り付けた後、VBE 上で日本語のコメントが読めることを確認する
- 万一コメントが文字化けしても動作には影響しない作りにしてある。シート名は「数字で始まるシート」で判定し、列名は1枚目の年度シートの見出しから読み取り、コード内で必要な日本語(「年度」「地区」「地区別_VBA」「_売上」)は文字コード(ChrW)で組み立てているため。化けるのはコメントと、メッセージの文面だけ
- Windows 版 Excel で使うときは `split_by_area.bas`(Shift_JIS・CRLF)を VBE の「ファイル → ファイルのインポート」で取り込む。Windows の VBE は UTF-8 の .bas だと日本語が化けるので、こちらは Shift_JIS のままにしておく。GitHub 上で `split_by_area.bas` を開くと文字化けして見えるが、ファイルは壊れていない
- コードを直すときは `split_by_area.txt` と `split_by_area.bas` の両方を同じ内容にすること

うまくいかないとき

- 保存のたびに許可のダイアログが出る → いったん中止し、「アクセス権を付与」で `sales_data.xlsx` のあるフォルダそのものを選び直して再実行する
- 「年度シートが見つかりません」と出る → `split_by_area.xlsm` のほうが手前になっている。`sales_data.xlsx` を手前にして再実行する
- 途中でエラーになって止まった → VBE の「実行 → リセット」を押し、開いたままの新しいブックを保存せずに閉じてから再実行する

## 元データを作り直すとき

- `pip install pandas openpyxl` のうえで `python make_sales_data.py` を実行する
- 地区ごとの規模や伸び率は `make_sales_data.py` の `areas` の数字で決めている。ここを変えたら、ノートブックの保険セルにも同じコードが入っているので、そちらも同じ内容に直すこと
- 作り直した `sales_data.xlsx` を push すれば、受講者のノートブックは新しいデータをダウンロードする
